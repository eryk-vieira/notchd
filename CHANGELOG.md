# Changelog

All user-visible changes. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/). The version is `manifest.json`'s. Released sections are never edited.

## [Unreleased]

### Added

- A [Herdr user module showcase](docs/examples/modules/herdr/) that puts agent metrics above a Herdr terminal and peeks on blocked or completed work. It installs from the example folder without a daemon rebuild.
- A reusable notchd agent skill teaches coding agents to inspect and control a running daemon through `notchd ipc`. `notchd --skill` prints the copy bundled with the binary, and programs in notchd terminals inherit the exact binary, socket and instance to reach their own daemon.

### Fixed

- GNOME: the notch's text, the terminal's included, follows the desktop's text scaling (Settings, Accessibility, Large Text, or `text-scaling-factor`), at once when it changes, and the open notch widens with it so the labels keep their room; it stayed at its own fixed sizes and looked smaller than the rest of the Shell. A new accent color or color scheme also reaches the module views and tabs at once; they kept the old look until the notch's state changed.

## [0.7.1] — 2026-11-04

### Fixed

- GNOME: the notch takes the top bar's colors (its background and text) instead of Adwaita's window colors, so it reads as part of the bar with the default Shell theme, the light color scheme and other Shell themes.
- Omarchy: a notch added on the top or bottom edge of a screen that already has a notch on a side edge now draws at once; it showed only an empty shoulder until the shell restarted, with hundreds of binding-loop warnings in the log.

## [0.7.0] — 2026-11-04

### Changed

- GNOME terminals now draw directly inside the notch using the daemon grid; they no longer open a separate GTK window. Their theme colors reach the emulator in the required hex format, their configured font is honored, and composed text goes through the Shell input method. Configured terminals now have settings pages in the daemon's schema, including their command, size and font. Workspace choices in GNOME preferences include the compositor's reported workspaces.
- GNOME notches on one edge now pack beside each other, join their outlines and share the row's depth; side notches clear occupied corners. Closed notches respect workspace and fullscreen visibility. If the preferences process exits unexpectedly, its D-Bus presence disappears and the extension releases the daemon's settings state.
- GNOME preferences now keep page reports separate from opening the window, so a late report cannot reopen settings after a quick close.
- GNOME expanded views scroll when their content is taller than the screen, with a scrollbar and mouse wheel support.

### Fixed

- GNOME 51 terminals now send Enter through the input method's activation signal when its key event is consumed, while GNOME 46 keeps its existing key handling.
- GNOME expanded notches now shrink to the monitor's available width at fractional or high display scales, keeping the terminal inside the card on narrow logical screens.

## [0.6.0] — 2026-11-03

### Changed

- Terminals in the notch (`claude`, `codex` and your own) are notchd's own now: the daemon emulates them with Ghostty's libghostty-vt and the UI draws the screen, so the `qmltermwidget` package (Omarchy) and VTE for GTK 4 (GNOME) are no longer needed. What it brings: the kitty keyboard protocol (Shift+Enter and the like reach Claude Code and Codex), the mouse for programs that ask for it, kitty images, your theme's ANSI colors (Omarchy reads them from the theme's `ghostty.conf`), selection with the mouse (Shift over a program that has the mouse), Ctrl+Shift+C and Ctrl+Shift+V, a program's OSC 52 copies, dead keys and input methods. Heavy output is drawn 2 to 2.6 times as fast at under half the CPU; full-screen redraws cost about twice as much for now. A dropped connection to the daemon is made again instead of ending the view. `make restart` no longer installs anything. See "Terminals" in `docs/architecture.md`.
- Building the daemon needs zig 0.15.2 and git (for Ghostty's source): `make` downloads that zig into `build/zig`, its checksum checked (`scripts/fetch-zig.sh`).

### Fixed

- `scripts/install.sh` starts the daemon itself (`notchd daemon --ensure`) where `systemctl` is installed but no systemd user manager runs (a container, a session without systemd), instead of ending with "could not start notchd.service" and no daemon.

## [0.5.0] — 2026-11-03

### Added

- Icons in a module's view can have a `name` (`media-playback-start`, `window-close`...) next to the Nerd Font `glyph`, so a UI without Nerd Fonts can draw its own symbol; `glyph` stays as the fallback, and an `icon`'s `size` can be a text size. The built-in modules send both; nothing changes on screen. See "Named icons" in `docs/architecture.md`.
- `scripts/install.sh` installs the daemon on Ubuntu, Fedora and other distributions: it downloads the release `native/releases.json` pins, verifies its SHA-256, puts `notchd` in `~/.local/bin` and runs it as a systemd user service; running it again upgrades, `--uninstall` removes it and keeps `~/.config/notchd`.
- A GNOME Shell extension (`hosts/gnome/`, GNOME 46 and later) draws the notch on Ubuntu's and Fedora's default desktop, from the same daemon: every edge and drag, the view primitives, guests, room for the top panel and a dock, a settings window (the extension's preferences) and terminals in the notch (with VTE for GTK 4). `scripts/install.sh --extension` installs and enables it, with a starter config when there is none; `--binary` installs a build of your own before the first release. See "GNOME UI" in `docs/architecture.md`.

### Changed

- The Voice disc moves smoothly with the voice: each level eases over 140 ms instead of 90, so the disc no longer stops between the levels that come about ten times a second.
- The daemon now carries its own built-in modules' settings (titles, fields, defaults) and the Python files it runs for voice and the optional components, so a host (the Omarchy plugin, and any later UI) no longer sends them or tells the daemon where its `core/` folder is: the release is the one `notchd` binary, which writes those files under `~/.local/share/notchd/sidecars/` the first time it needs them. Nothing changes on screen. `coreDir` in the `catalog` message still works but is deprecated; `NOTCHD_CORE_DIR` points the daemon at a checkout's files for development.

## [0.4.0] — 2026-11-02

### Added

- You can write your own modules, in any language: a folder in `~/.config/notchd/modules/<id>/` with a `module.json` and a program that prints JSON lines for the notch and reads its clicks. Settings declared in `module.json` get a page in the settings window and reach the module as `config`; it can subscribe to CPU and memory, the media players, the screens and the agents' plan usage, post a desktop notification and peek. It reloads when you save, and errors show in the notch with a Restart button and the log's path. Samples in `docs/examples/modules/` (shell, Python, Node); the guide is "User modules" in `docs/modules.md`.
- Voice, Codex Live and the optional components now run in the daemon. `codex-live` and `local-live` (the module logic, the transcript, the levels, mute, stop and new, the `live` IPC) and the components' installer calls and state (the Components page, the rows on the module pages, the choices locked until a voice is installed, the `component` IPC) are the daemon's; the Python bridges and the installer are unchanged and run by it. They look and answer as before, except that the red dot of the closed notch no longer swells with the microphone (it does in the open view), the disc is accent-colored while idle too, and a locked choice follows an edit of the language after the daemon answers (a few milliseconds). A conversation only sends the notch its levels (some ten small messages a second) while its open view is on screen. A new `notchd ipc component status | install <id> | cancel <id> | remove <id>` drives the installer from a script; an installation still runs apart from the settings window and survives closing it and a shell reload.
- The media module now runs in the daemon too: it reads the players over MPRIS itself (no Quickshell MPRIS service) and the notch draws its views. It looks the same, with two small differences: the cover corners follow the theme's two radii, and with a long title and artist they share the room instead of the title keeping it first. The daemon does not touch the session bus until the module is listed, and the progress bar runs on in the notch without a stream.
- Terminal sessions survive a shell reload. The `claude` and `codex` agents and the terminals of your own now run in the daemon, not in the shell: the program is a terminal the daemon owns, so `make restart`, a crashed shell or a reloaded plugin no longer ends your conversation; the notch comes back to the same session and draws what the agent had on screen. The program still starts the first time the notch opens, keeps running while it is closed, and ends with the daemon, when you restart it from the notch, or after `idleMinutes` closed and idle. Their plan usage, titles, working dot, done peek and `agent`, `claude`, `codex` and `terminal` over IPC are the daemon's now and look and answer as before (the shell's own IPC target answers `ok` for them once the command is sent; `notchd ipc agent ...` has the module's own answers). `notchd attach term:claude` shows a session on your terminal.
- The timer, activities, resources and OSD now run in the daemon (`native/notchd-modules`), and the notch draws what they send, as it draws any module that lives in the daemon: a new `CoreModule` type shows a daemon module's views, facts and settings page like a QML module's, and a user module the daemon runs shows through it too. They look and answer as before: `timer`, `push` and `clear` over `notchd ipc` give the module's own answers (the shell's IPC target answers `ok` for them, as it cannot wait for the daemon), and the Omarchy `osd` target forwards to the daemon. The primitives got `width`, `height`, `minWidth`, a row's and column's `maxWidth`, and a button's `big`.
- The daemon now decides the notch state: hover delays, pinning, tabs, peeks and where they go, navigation, which screen each notch is on and the space it keeps clear are computed in `notchd`, and the shell shows what it says. Nothing changes on screen (the hover delay holds within a few milliseconds); while the daemon is away the notch stays as it was under the "notchd not running" row. A config with lists (`notches`, `modules`) edited by hand while the shell runs is read as lists now.
- The daemon now owns the config and the settings schema: it reads, watches and writes `config.json` (atomically; defaults are still never written), and the settings window gets its pages and fields from it, looking and behaving the same. The daemon also restarts itself: when it dies while the shell runs, the shell starts it again after a short backoff, and until it answers the notch shows a small "notchd not running" row at the top of the screen (after a second and a half, so a start does not flash it) and keeps your last config; settings you change meanwhile are applied when it is back. `qs ipc call ... set` and the rest of the IPC surface are unchanged.
- The notchd daemon now starts with the shell, on Omarchy and standalone: the host runs `scripts/ensure-daemon.sh`, which finds the `notchd` binary (`$NOTCHD_BIN`, `PATH`, `~/.local/share/notchd/bin/notchd`), starts the daemon detached (it outlives a shell restart; its log is `~/.local/state/notchd/daemon.log`) unless a daemon of the same version runs, and connects to it. It runs in shadow for now: nothing changes on screen, and if it cannot start the shell logs it once. `notchd daemon --ensure` starts the daemon detached and prints its socket; a daemon of another version is replaced through the new `shutdown` IPC method. `make dev` builds the daemon and runs it as its own `dev` instance with the dev config; `make restart` builds it and, when the build differs from the installed one, stops the running daemon and copies the build to `~/.local/share/notchd/bin/notchd`; an unchanged daemon keeps running, with its sessions.
- Voice (`local-live`), the cascade alternative to Codex Live: a spoken conversation whose speech recognition ([Voxtype](https://github.com/peteonrails/voxtype), the one Omarchy dictates with, with the model and language it is set up with) and voice ([LocalAI](https://localai.io), text to speech) run on this machine, and whose words go into a normal text session of Codex or Claude Code, resumed (`last`, the most recent in its folder, by default; `new`; or an id), so voice is one more input to the conversation you also type in. Same disc, transcript and `live local-live start | stop | toggle | new | mute | unmute` IPC; half duplex for now (the microphone is ignored while it answers). Voice runs on LocalAI's HTTP API (`/v1/audio/speech`), so any text-to-speech model it has works: Settings › Modules › Agents › Voice has the agent, folder and what it may do; then speech to text (STT) and text to speech (TTS) as two sections: for STT, the language you speak (a choice: Voxtype's own, auto-detect, Português, English, Español, Français, Deutsch, Italiano, Nederlands) and the speech model; for TTS, the language it speaks (the same, Portuguese by default) and the engine (Piper or Pocket TTS; or any model of your LocalAI by name), its voice, and LocalAI's address; only the voices of the chosen language show. notchd's own LocalAI (the official binary, in `~/.local/share/notchd/localai`, no Docker, no root) is started on `127.0.0.1:18080` when a conversation or an installation needs it and stopped with it; one that already answers at the address is used as it is. Not loaded by default.
- Optional components, installed, removed and configured from the settings: nothing heavy ships with notchd. A new Components page lists everything the voice modules need beyond the app, with its size and state (not installed, a bar with the percent while it downloads or installs, installed with what it uses, or why it failed), and Install, Cancel and Remove buttons (Remove asks twice). The same rows are on the Voice and Codex Live pages. LocalAI (197 MB) is a download; its voices (one Piper and one Pocket TTS per language, Portuguese, English, Spanish, French, German, Italian and Dutch, all on the CPU: Piper 63 to 120 MB each, Pocket TTS 750 MB, 1.3 GB for English; the engine's own backend, 78 MB and 1.2 GB, is downloaded once and shared) are installed through its own API, with the bytes it reports as the progress, and a first sentence that makes the backend fetch its weights; Voxtype (an AUR package, built by yay or paru in a terminal), the audio tools and Codex Live's GStreamer set are packages, installed through a polkit prompt (pkexec) or, with no polkit agent, in a terminal that runs sudo, and never removed from here. Removing a voice keeps what another installed voice of its engine still needs (the backend, the other languages' weights); removing LocalAI removes the voices it holds. An installation runs apart from the settings window: close it and it goes on, open it again and the bar is there; Cancel cleans up, a failed download resumes. Voice's voice choices are locked until installed. A module that lacks one now says "Install X in Settings › Components" instead of naming a `make` target; `make live-deps`, `local-live-deps` and `live-models` are gone.
- Codex Live (`codex-live`), a spoken conversation with Codex: open its notch with a click or a shortcut and talk; it answers aloud, and what you ask it to do it does in its folder, in a thread of its own (only reading there, unless its May setting lets it change files; it never asks for approval). It runs on the ChatGPT login Codex keeps, through Codex's realtime conversation (`codex app-server`, over WebRTC). A disc swells with its voice. The transcript shows under it; the microphone is on only while the notch is open on it (a red dot that swells as it hears you), with the speakers' echo taken out, and the restart button starts a new session with the transcript cleared. Settings: Modules › Agents › Codex Live (command, folder, voice, what it may do). Over IPC: `live codex-live start | stop | toggle | new | mute | unmute`. Settings › Components installs what it needs with pacman (GStreamer's WebRTC, about 8 MB). Each session's log is `~/.local/state/notchd/codex-live.log`.
- Settings: a `choice` field can show as wrapping chips (`display: "chips"`), for a long list of short options, such as Codex Live's voices.
- Terminals of your own: each entry of the config's `terminals` (`"btop": { "title": "System", "command": "btop" }`) is a module that runs its command in a terminal in the notch, shown by any notch that lists its id. The command is a shell command line (`cd ~/app && npm run dev` works), run in your home unless its `directory` says otherwise; the closed notch shows the title the program gives the terminal. Its other settings live under its id, like an agent's (folder, stop when idle, size, font). The settings window makes them too: Modules › Terminals › Add terminal starts one running your shell and opens its page (title, command, folder, size), and its trash can removes it, from every notch as well. And `terminal <id> toggle | new | "ask <text>"` drives it over IPC. An agent's width and height now go down to 320 and 120 px in settings, as the terminal itself already allowed.
- Navigating the notches from the keyboard: `navigate` over IPC (bind it to a key, e.g. SUPER+N) highlights every notch, hidden ones included, with a small label at its top right: its number and name. `1`–`9` or the arrows (`h`/`l`) select one, which opens as a preview while the others show closed; `Tab` walks its tabs, `Enter` pins it open (the other notches close) and `Esc`, Ctrl+Esc or the shortcut again leaves everything as it was. Keys also act on the selected notch: `s` opens its settings, `x` twice removes it, and `m` moves it (arrows for the edge, Shift+arrows along it, Tab for the monitor; Enter keeps it, Esc puts it back).
- Any notch pinned open (a click, a shortcut, navigation) takes the keyboard, not only an agent's: Escape or Ctrl+Escape closes it, and a focus or workspace shortcut that moves to a window closes it too. Never on hover alone. A notch opened on the monitor without focus no longer closes at once: it keeps the keyboard until Escape.
- Plan usage for `claude` and `codex`: the open agent shows a bar per limit (5 hours, the week, a model's week) with how much is used and when it resets, and peeks once when one passes 80 % (`usageWarn`) and when it is reached. notchd asks the endpoint each CLI calls, every 5 minutes and when the agent finishes a task, with the login the CLI keeps, which it only reads; when that lapses, the last figures stay, marked stale, until the agent renews it. Settings: Modules › Agents › its gear › Usage.
- Agents, a kind of module of their own: `claude` and `codex` are listed apart on the Modules page, under Agents, and share one set of fields (folder, command, stop when idle, size, font), which a new agent gets by saying `"agent": { "command": ... }` in its JSON file. `agent <id> toggle` opens or closes the notch that shows an agent, on its tab, whatever the notch is called; bind that instead of `toggleNotch <name>`, which renaming the notch breaks. `agent <id> new` and `agent <id> "ask ..."` do what `claude new` and `claude "ask ..."` do, which stay.
- An agent without a folder of its own starts in notchd's: `notchd` in your Documents folder, made the first time, instead of your home.
- The README image shows the agents: Claude and Codex in the closed notch, a plan-usage warning, a script's fine-tune, and Claude open in its terminal with its limits; the OSD left it.
- Leaving the notch from the keyboard: Ctrl+Escape in the `claude` or `codex` terminal closes the notch (the agent goes on), and a focus or workspace shortcut that moves to a window closes it too. Before, the open notch kept the keyboard until a click away.
- Tabs (`tabs`, on by default; settings: Notches › its gear › Layout › Tabs): a notch with several modules shows one at a time open, with a tab for each, instead of all of them one above the other. Opening the notch from a module (a shortcut, `claude "ask ..."`) picks its tab. Closed, it shows every active module side by side, not just the highest-priority one. `tabs: false` brings back the old way.
- Icons for idle modules (`idleIcons`, on by default; settings: Notches › its gear › Layout): a module that is active with nothing to show closed, like a timer that isn't running, shows its icon in the closed notch. Modules declare it with `icon`.
- News you missed while the notch was open: an agent that finishes while you look at another tab gets a dot on its tab and on the closed notch (until you open it), and its peek shows as the notch closes. Modules set `attention` for it.
- `claude` and `codex` modules: Claude Code and Codex in their own terminal UIs inside the notch, in a terminal from the optional `qmltermwidget` package (`make restart` installs it with pacman; without it, the notch says what to install). The closed notch shows the session's title, which the agent makes after the first message, read from the title it gives the terminal, and a green dot while it works; open, the terminal takes the keyboard, Escape included, and closes from its × button or the shortcut. The agent starts the first time the notch opens and keeps running while it is closed, peeking when it finishes something; the restart button, or `claude new` / `codex new` over IPC, starts a new one, and `claude "ask <question>"` opens it and types the question in. The terminal takes the theme's background and foreground. Settings: Modules › Agents › Claude, › Codex (folder, command, width, height, font, stop when idle). Not loaded by default: give each a notch of its own and bind `agent <id> toggle` to a key.
- Modules you type into: the notch takes the keyboard while it is pinned open, by a click, a shortcut (`toggleNotch`) or a press on the module's field (`requestKeyboard()`), never on hover alone; Escape closes it. Modules can also set their expanded view's width (`expandedWidth`), and open or close their notch (`openNotch()`, `closeNotch()`).
- An app icon: the notch with an orange dot and an `n`, in Gruvbox colors. `assets/icons/` has the SVG, PNGs at every size from 16 to 1024 px, a `.ico` and a one-color symbolic SVG.
- Omarchy: a notchd button in the bar, with the app icon. Its panel lists every notch, where it is and what it shows; clicking one opens or closes it, its gear opens that notch's settings, and Settings (or a right click on the icon) opens the settings window.
- `timer` module: a countdown or a pomodoro, started from the expanded notch or with `timer 25m`, `timer pomodoro`, `timer toggle`, `timer +5m`, `timer stop` over IPC. The closed notch shows the time left; at the end it peeks, even over the open notch, and sends a desktop notification. Its lengths, rounds, auto-start and notification are in settings (Modules › Timer). Not loaded by default.
- `media.equalizer` (settings: Modules › Now playing › Equalizer): `"smooth"` (the default) glides the bars at 60 fps, `"light"` makes them jump about six times a second, for less CPU.
- `resources` module: CPU, memory and the disk holding `/`, each with a bar and how much is used in the expanded notch, and their percentages in the closed notch. One that runs short (90 % or more; the CPU for about 10 s in a row, so a burst doesn't count) turns red and peeks once. `resources.compact: "short"` (settings: Modules › Resources › Closed notch) keeps them out of the closed notch until one runs short. Not loaded by default.
- Modules can have settings of their own, declared with their title in a JSON file next to the module (`media.json`) and read with `setting(key)`: stored under the module's id, shown on the module's own page, loaded or not.
- Notches never sit on each other: on the same edge of a monitor they go side by side, each as near its `offset` as the others let it, and make room when one grows. An open notch grows over its neighbors, which hide until it closes.
- Standalone modules (`"standalone": true` in the module's JSON file): a fixed job and a place of their own. No notch shows one, even one whose `modules` list it. It loads unless `<id>.enabled` is `false`, peeks on the monitor you work on where `<id>.position` (`edge`, `offset`) says, top center by default, and draws over any notch there, which hides until it goes (settings: Modules › its gear). The Omarchy OSD is one, so `osd` is no longer in the default `modules`.
- Modules can set `peekOnFocusedScreen`: their peek shows once, on the focused monitor only, in the first notch there that shows the module, else at the top. For feedback on what you just did there.
- Settings: the Notches page lists the notches, where each is and what it shows; a gear opens a notch's page with everything it has of its own (name, modules, compact style, position, workspaces), and Add opens the new one's. A Modules page lists every module, notch modules and standalone ones apart, with where each shows (or whether a standalone one is on) and a gear to its own settings, even while no notch shows it. General comes first and has what applies to every notch.
- Several notches (`notches`; settings: the Notches page, a gear per notch): each with its own modules, compact style, position, workspaces and reserved space, inheriting the top-level keys it leaves out. A module may show in several. IPC gets `openNotch`, `closeNotch` and `toggleNotch` by notch id, and `state` lists the notches and their copies.
- `position.screen: "all"` (settings: Notches › Position › Screen › Every screen): a copy of the notch on every monitor, each hovered, pinned and dragged on its own. A peek shows on the focused monitor only, so changing the volume on one monitor no longer takes the notch away from the music playing on another.

- Drag the notch onto another monitor: a preview shows it there, and the drop makes that monitor its home (`position.screen`; settings: Notches › Position › Screen), where the notch stays whichever monitor has focus, peeks included; a peek also shows at the top of the monitor you work on when no notch there shows it. Dropped on a workspace left out of `workspaces`, it adds that workspace, so the notch stays where it landed. Reserved space is kept on the home monitor only.
- Settings window with a sidebar of pages (General, Notches, Modules, Appearance), fields grouped by section, the edge picked from picture cards, segmented choices and switches for modules.
- Settings fields can be `boolean` or `note`, live on a `page`, and show a choice as picture cards (`display: "cards"`); hosts can add pages with `hostSettingsPages`.
- Theme tokens derived from the host's colors (`muted`, `faint`, `line`, `hover`, `selected`, `surface`, `danger`, `success`, radii). The Omarchy host takes `success` from the theme's `green` in `colors.toml`.
- `make check`: Node tests, QML behaviour tests, qmllint, plugin validation and offscreen visual scenarios.
- `reserveSpace` (settings: Notches › Layout › Keep windows clear): windows tile below the closed notch instead of under it. The space follows the closed notch, a sliver at rest and a compact notch's height while a module is active; peeks never move windows.
- `workspaces` (settings: Notches › Layout › Workspaces): the workspaces the closed notch shows on. On others it moves to a screen that shows one, or hides; peeks and the open notch still show, and reserved space is only kept where the notch can hang. Hyprland only.
- `position` (settings: Notches › Position): the hanging notch on any screen edge (`edge`: top, bottom, left, right) and anywhere along it (`offset`). On a side edge peeks and the expanded notch keep their layout and the notch grows sideways; reserved space moves to that edge.
- Hold the hanging notch for a moment and drag it to any edge (`draggable`, on by default; settings: Notches › Position › Drag to move); a quick click only pins it. It follows the nearest edge as you drag, snaps to the middle, and the drop is saved as `position`. Windows move once, when it lands. `recenter` over IPC puts it back at the top.
- Modules can give `verticalCompact` and `verticalPeek` views for a side edge; a module without a vertical compact view shows a dot there. The media and activities modules stack their compact view down the edge, and the Omarchy OSD stands its bar up.
- Settings fields can be a `number` (a slider with a fractional step, shown as a percentage with `display: "percent"`); card pictures get their option's `value`.
- README image of the notch in its four states, rendered from the real QML with `make hero`, in Omarchy's Gruvbox theme and wallpaper.

### Changed

- Installing a voice: each step LocalAI does is checked sooner at first (from 20 ms, up to every half second), so one that ends at once, such as a backend already there, no longer waits half a second.
- The expanded notch has no gear any more. In Omarchy the settings open from the notchd button in the bar; anywhere, with the `settings` IPC method.
- At either end of its edge the notch sits flush in the corner, square against the screen's side (or the bar), instead of short of it by its shoulder.
- Notches that come within a few pixels of each other on one edge (or are dropped near one) join flush into one shape, as deep as the deepest of them. One that opens grows from where it is and pushes the others aside, evenly in the middle of the edge and away from the screen's side against it, instead of hiding them.

- Modules read `notch.expanded` and `notch.peeking(module)` instead of `notch.mode` and `notch.peekModule`, since a module can show in several notches. Hosts read the place and workspaces from each notch (`service.notches`); `NotchSurface` no longer takes a `compositor` of its own.

- The repository root is the Omarchy plugin (`manifest.json` at the root). Point `~/.config/omarchy/plugins/eryk.notchd` at the checkout instead of `hosts/omarchy`.
- The standalone host is `shell.qml` at the repository root: run `qs -p <checkout>` instead of `qs -p hosts/standalone`.
- Documentation split into README (users), `docs/` (reference), DEVELOPMENT.md and CLAUDE.md.
- Hosts tell the service which edge their bar is on (`NotchService.barEdge`) instead of `NotchSurface.barOnTop`. The Omarchy host follows the bar's position, so with a bottom or side bar the notch drops out of it.
- Picking a field's default in the settings window removes the key from the config instead of writing the default.
- The compact media view shows the track's title and artist between the artwork and the equalizer, cut short past 240 design px; the artist drops out when there is no room for it.
- The compact notch is shorter (28 design px instead of 36), close to a bar's height: tighter padding, smaller corners, and smaller media artwork and activity icon.

### Fixed

- A user module in `~/.config/notchd/modules/` now shows in the settings like a built-in: in the Modules page, in each notch's list of modules (to turn on), with its own page for the `settings` of its manifest and, if it says `standalone`, its place. The daemon had it all, but the settings window listed only the modules it read from its own files.
- After the daemon is killed, the shell always reconnects to the one it brings back: a race could leave it with no attempt pending, and "notchd not running" stayed until a settings edit.
- An open notch that follows the focus stays on the screen the pointer opened it on, instead of jumping to another screen when the focus moves while it is open.
- `claude` and `codex` down a side edge: the working dot sits on the mark's corner, instead of keeping an empty place under every mark while it is off.
- An open notch taller than the screen was cut off at the bottom, with no way to reach the rest: two terminals on a laptop screen, say. Past the room the screen has, its modules now scroll, with the wheel and a scrollbar.
- Switching a monitor off and on again no longer leaves its notches gone: they move to another monitor while it is off and come back to it, with the space they reserve.
- About 1300 binding-loop warnings in the log at start (and wasted work) with notches on a top or bottom edge and a side edge of one screen: the corners' insets read every notch's place, the side ones' included, which come from those insets.
- A notch in `notches` dragged to the top edge (or to the middle, or off its home screen) jumped back: the drop left out what equals the default, and the notch took it from the top-level `position` instead. The drop now writes whatever differs from what the notch inherits.
- Media artwork took a texture atlas the size of the monitor (about 25 MB) for an 80 px cover; it now gets a texture of its own, and scales down smoother.
- The default notch kept a window covering each monitor even while it showed nothing, about 25 MB of buffers; its windows now exist only while it shows a peek, and for 5 s after. A peek that needs it again after that shows about 50 ms later.
- A running timer redrew the notch four times a second; it now wakes as its clock turns, once a second, so the open notch's progress bar steps once a second too.
- Music playing cost a quarter to a third of a CPU core (on a 160 Hz monitor) and kept the compositor busy: the hidden default notch drew the media view on every monitor, and the equalizer and the progress bar never stopped easing. It now costs about 1 %: hidden copies hold no view, the equalizer and the progress bar move at 60 fps instead of the monitor's rate (8 % of a core while music plays, under 1 % of a 20-thread CPU), and a notch hidden over a fullscreen app stops its equalizer.
- The notch's animations looked choppy at their slow end: one side of the outline moved a whole pixel at a time while the other glided. It now moves in fractions of a pixel and settles on whole pixels, with its content kept on whole pixels throughout.
- Moving the pointer across the open notch's controls (the media buttons) closed and reopened it: those controls took the hover from the notch.
- With `reserveSpace`, windows took 4 s to reclaim the space after the last module ended; they now do as the notch finishes collapsing (400 ms).
- Media artwork, and its placeholder, vanished entirely under Qt's software renderer; it now shows with square corners there.

### Removed

- The compact view in the bar (`compactStyle: "bar"`, which was the default): every notch hangs from its edge. A config that still sets `compactStyle` changes nothing, so a notch that was in the bar now hangs from the top, in the middle; drag it or set `position` to move it. Modules lose `barView`, and the service `barStyleAvailable` and `barNotch`.
- `scripts/build-omarchy.sh` and `dist/`: no build step is needed any more.
